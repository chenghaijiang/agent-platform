# ADR-015：智能体能力全景分期与自研内核裁决

- 状态：已接受
- 日期：2026-11-14
- 关联：ADR-012（Agent 执行域架构/三层协议留缝）、ADR-013（执行边界安全模型）、ADR-014（统一工作台）
- 来源：grill-with-docs 审问第二轮裁决（Q7–Q12 按推荐接受；Subagent 与 Context Compact 由用户前移至二期最前）

## 背景

用户对「智能体」提出 20 项能力全景（Agent Loop / Tool Use / Permission / Hooks / TodoWrite / Subagent / Skill Loading / Context Compact / Memory / System Prompt / Error Recovery / Task System / Background Tasks / Cron / Agent Teams / Team Protocols / Autonomous Agents / Worktree Isolation / MCP Plugin 及其子项）。现有 Agent 执行域建在 LangGraph StateGraph 上（ADR-012），需裁决基座与分期。

## 决策

1. **能力全景三期划分**：
   - **第一期（统一工作台 MVP）**：Agent Loop（最小 while 循环，串行工具）、Tool Use（dispatch map）、Permission（复用 `agentdesk/policy.py`）、System Prompt 运行时分段组装、TodoWrite（= 计划卡片，先计划后执行）、Error Recovery（重试 + fallback 模型）、Hooks（PreToolUse/PostToolUse 最小实现）。
   - **第二期（自研内核主线，开工即做前两项）**：**Subagent（fresh messages[] 上下文隔离）→ Context Compact（snip/micro/budget/auto 四层压缩）→** Skill Loading（SkillManifest 按需注入）→ Memory（selection/extraction/consolidation）→ Task System（TaskRecord/blockedBy）→ Background Tasks（线程执行 + 通知队列）→ Worktree Isolation（WorktreeRecord 任务-目录绑定）→ Tool 并发。
   - **第三期（多智能体社会层与插件）**：Cron Scheduler（持久化调度/会话级触发）、Agent Teams（MessageBus/收件箱/权限冒泡）、Team Protocols（关机握手/计划审批）、Autonomous Agents（空闲循环/自动认领）、MCP Plugin（多传输/通道路由/工具池组装）。
2. **内核基座 = 自研循环内核（方案 A）**：新建 `src/agent_platform/agent_runtime/` 模块（`while True + stop_reason + TOOL_HANDLERS dispatch + hooks`），状态持久化自建（复用 PG 租约/事件表模式）。理由：Subagent 隔离、Teams 收件箱、空闲循环是运行时自身行为，硬塞 LangGraph 属框架错位；ADR-012 三层协议本为可插拔引擎留缝。LangGraph 保留给 QA RAG 图。代价：自建 checkpoint 快照持久化，放弃 LangGraph 恢复生态。
3. **第一期驱动路径 = 桥接现有 agentdesk 图（方案 A）**：聊天框调既有 API 创建 Task、SSE 桥接 `task_events` 到聊天流、审批卡片调 confirm/decide 端点；自研内核第二期开工后逐项吸收旧图，避免一期双风险。
4. **会话 ↔ Task = 1:N**：会话内一条驱动消息创建一个 Task，聊天流按 Task 分组渲染；`agent_tasks` 加 `chat_session_id` 外键（仅归属，不改变 Agent 域/渠道层分治，ADR-011 语义不变）。
5. **聊天消息持久化 = 新增 `chat_messages` 表**：会话级消息流水（`session_id, seq, type, data, task_id`），SSE 携带 seq 支持 Last-Event-ID 续传；checkpointer 继续只管 QA 图执行态。卡片消息可查询、可回放，服务重启恢复验收不受影响。
6. **Hook 机制 = Python 注册表**：`HOOK_REGISTRY[("pre_tool_use", fn)]` 代码级注册、随应用部署；否决目录热加载（exec 红线风险，ADR-013 安全模型拒绝）与 MCP 承载（阻塞至第三期）。

## 后果

**正面**：

- 终局架构清晰：自研内核承载能力全景，LangGraph 只守 QA 域，ADR-012 的「可插拔执行引擎」留缝被兑现为真实演进路径；
- 一期桥接零重写既有已验收图，风险最小；
- Subagent/Context Compact 前移使二期首个里程碑即解决长任务上下文瓶颈，为后续 Teams 打底。

**负面/风险**：

- 一期写一次性桥接代码（chat ↔ agentdesk API/SSE 适配层），二期内核吸收后拆除；
- 双执行引擎并存的过渡复杂度：桥接期行为一致性靠 golden 测试锁定；
- 自建状态持久化是净新增工程量（快照格式设计、恢复语义、租约协同），无现成生态兜底。
